# Работа над сайтом

Смотрим сюда во время работы над интернет-проектами:
https://app.notion.com/p/gorokhovatsky/3a6777056402808bb79df09beedc4161

Полный перенос завершён. Контрольная версия:
`51368c6dff6b2b04f903c5cc29aa1a81887ae13c`.
7 октября 2026 пользователь разрешил переработку и публикацию сразу на основном
адресе Pages. Исходник сохраняется в `source/` и на `/original/`; его контроль
не отключать. Новая главная находится в `site/`.
По прямому решению пользователя даты 12–25 октября и программа перенесены
на 2027 год как предварительная версия; дни недели должны соответствовать 2027.
Условия и набор ещё не объявлены. Весной содержание предполагается обновить.
Крупный DUSTY и композиция исходного футера — принятая основа; его градиент
меняется по погодной палитре. Состав и оформление нижних ссылок оставлены
на усмотрение реализации. См. [решения сезона](docs/season-2027.md).

Перед будущим изменением интерфейса читать относящиеся к задаче правила
[DD-01–DD-24](docs/redesign-rules.md), [арт-направление](docs/art-direction.md)
и их [источники](docs/redesign-sources.md).
Прямое решение пользователя: использовать максимум приёмов из поста
Bitter Glitter и кейса Hotline Camp, чтобы дать человеку побывать в Анталье
до решения о поездке. Свет, погода, материал, движение и исследование времени
составляют центральную задачу оформления. Не сводить её без запроса пользователя
к одному необязательному эффекту или погодному виджету.
В задаче и результате указывать применённые правила, проверку и ограничения.
Общие рекомендации не дают разрешения менять согласованный характер сайта
или выдумывать условия. Неподтверждённое записывать вопросом к организаторам.
Исключения из проектных правил описывать явно с причиной; прямые решения
пользователя имеют приоритет. Целостное арт-направление проверять прототипом
в нескольких состояниях; техническая корректность не заменяет художественную приёмку.

Для изменений сайта перед публикацией: `npm test`, визуальная проверка
затронутых поверхностей на широком и узком экране, проверка связанных действий.
Для полной переработки обязательны основные сценарии, меню, галереи, privacy
и проверки из DD-13–19. При смене реализации сохранить контрольный исходник
и осознанно обновить тесты: сейчас они проверяют точность переноса.
После публикации проверить успех GitHub Actions для точного коммита,
`release.json` и затронутое поведение публичной страницы GitHub Pages.

Для изменений только документации достаточно проверки ссылок, идентификаторов
правил и `git diff --check`; браузерная проверка сайта не требуется.
Разделять автоматическую проверку, рендер в браузере, физическое устройство
и исследование с людьми. Наличие правил не означает соответствие им сайта.
