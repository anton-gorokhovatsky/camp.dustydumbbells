## Отказ от широкого доступа

Первая реализация через встроенный SpreadsheetApp запросила у владельца
право видеть, изменять, создавать и удалять все его таблицы. Авторизация
не была завершена. Пользователь прямо отклонил этот объём доступа и выбрал
другой обработчик с доступом только к одному файлу. Развёртывание отменено.

Простая замена на getActiveSpreadsheet не решает задачу опубликованного
приёмника: Google указывает, что специальные методы привязанного документа
недоступны при запуске как web app. Основание —
[Container-bound Scripts](https://developers.google.com/apps-script/guides/bound).

Новая схема оставляет Apps Script только приёмником HTTP-запросов и использует
отдельную служебную учётную запись Google для Sheets API. Ей открыт
только указанный файл. Облачные IAM-роли и делегирование аккаунта владельца
не нужны. В манифесте скрипта явно оставлен единственный OAuth scope:
`script.external_request`; права владельца на Sheets/Drive не запрашиваются.
Запросы ограничены Google OAuth и API этой таблицы через urlFetchWhitelist.
Принцип доступа служебного аккаунта —
[Google Workspace: access credentials](https://developers.google.com/workspace/guides/create-credentials).

## Код

- `backend/google-apps-script/Code.gs`: поля, серверная проверка, блокировка,
  поиск прежнего ID, добавление строки и ответ без контактных данных.
- `backend/google-apps-script/ServiceAccount.gs`: краткоживущий токен
  выделенного аккаунта и запросы только в указанную таблицу.
- `backend/google-apps-script/appsscript.json`: явные узкие права приёмника.
- `site/application.js`, `application-validation.js`, `application.css`:
  клиентская проверка, отправка, ожидание, ошибка, повтор и подтверждение.
- `scripts/application-markup.mjs`: узкий адаптер. Удаляет класс обработки
  Tilda и идентификатор её приёмника, сохраняя оформление и локальные виджеты.

Секрет `SERVICE_ACCOUNT_JSON` вводится только в серверные Script Properties.
В `DD_CONFIG.serviceAccountEmail` указывается проверенный адрес выделенной
учётной записи. Приватный ключ не помещается в Git, артефакты, клиентский код
или сообщения чата. JWT не содержит `sub`: impersonation владельца нет.
Токены, ключи, тела заявок и исходные приватные исключения не логируются.

Клиент отправляет форму в скрытый фрейм; Apps Script после ответа Sheets API
возвращает postMessage с ID и случайным nonce. Клиент проверяет домен Google,
ID и nonce. Загрузка фрейма и непрозрачный fetch не считаются успехом.
При ошибке поля остаются заполненными. Неизменённый повтор использует тот же
ID; приёмник под блокировкой проверяет его в реальном столбце Q, включая
ситуацию, когда строка записалась, а ответ потерялся. Sheets API получает
`valueInputOption=RAW`, поэтому пользовательский текст не исполняется как формула.

## Оформление таблицы

По следующему запросу пользователя рассмотрены четыре совета из
[подборки Бюро](https://bureau.ru/soviet/tablitsy/):
[плотность и выравнивание](https://bureau.ru/soviet/20230503/),
[шапки и сортировка](https://bureau.ru/soviet/20210216/),
[роль линеек и обозначений](https://bureau.ru/soviet/20201229/),
[свободное поле](https://bureau.ru/soviet/20201013/).
Перенесены принципы, соответствующие работе со списком заявок: короткая шапка
по верхней линии, ширина по содержанию, прямой горизонтальный текст,
группировка связанных данных и отсутствие лишней сетки. Это собственное
применение к Google Sheets, не буквальное воспроизведение примеров Бюро.

Основной вид A:H помещается при 100% в окне 1512 px: имя, статус, время,
телефон, Telegram, email, поездка и пожелания. Шапка и имя закреплены.
Фон белый, сетка скрыта, под шапкой тонкая линейка; Arial 11, подписи слева
и сверху, имя выделено весом. Цвет обозначает четыре реальных статуса,
которые доступны и текстом в нативном списке. I:P свёрнуты в группу
дополнительных сведений, K:P — вложенная группа партнёра; Q:R скрыты как
технические поля. Все исходные данные сохраняются на том же листе.

В настоящем Google Sheets просмотрены основной вид, раскрытие группы,
время и четыре варианта статуса. После проверки восстановлен основной вид.
Контроль значений до и после перестановки не нашёл потерь или подмен.
